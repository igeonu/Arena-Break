## 1장 — 플레이어 이동과 사격

### 1-1. CLAUDE.md 작성
- **실험 프롬프트**: "적 체력을 담을 간단한 클래스를 만들어줘. 현재 체력을 public 필드로 노출해서… 파일은 만들지 말고 코드만 보여줘."
- **관찰 포인트**: 규약(public 필드 금지)을 어기는 요청에 AI가 프로퍼티로 바꾸거나 되묻는다면 CLAUDE.md가 작동하는 것이다.
- **결과(현재 CLAUDE.md)**: 네이밍, 성능, 설계, 주석 규약, 작업 규칙 7개, MCP 사용 범위 표가 들어 있다.

### 1-2. 플레이어 이동 — 커밋 `5129bfd`
- **프롬프트 핵심**: InputActionAsset 1개 + `FindActionMap("Player")`, 상하 -80~80°, 중력 -20, 커서 잠금, 첫 프레임 delta 상한.
- **결과**: `PlayerController.cs`(115줄). 같은 커밋에 `WeaponSystem.cs`도 함께 들어갔다(1-3을 따로 커밋하지 않음).
- **교훈**: 구현 방식을 지정하지 않으면 PlayerInput, 직접 폴링, 액션 참조처럼 결과가 갈린다. MCP가 "연결했습니다"라고 해도 다시 읽어 실제 값을 확인한다.

### 1-3. 사격 시스템
- **프롬프트 핵심**: Attack 액션, R 재장전은 코드에서 InputAction 생성, 0.15초 연사, 50m, 노란 디버그 구체(Collider 제거), 12발, 1.5초 재장전.
- **비교 실험**: 새 대화에서 "총 쏘는 기능 만들어줘" 한 줄로 요청 → 파일 개수, 요청하지 않은 기능, 숫자의 출처, 씬 수정 여부를 표로 비교한다.
- **함정**: Console의 `Collapse`가 켜져 있으면 재장전 뒤 로그가 늘지 않는 것처럼 보인다.

### 1-4. 과제 — 조준(B) 선택 · 커밋 `bcaaba1`
- **결과**: `AimController.cs`(94줄)를 새로 만들었다.
- **⚠ 확인할 실패 후보**: 과제 조건은 "기존 PlayerController / WeaponSystem을 수정하지 않는다"였다. 그런데 이 커밋에서 `PlayerController.cs`(+5/-?)와 `WeaponSystem.cs`(+6)도 바뀌었다.
  → **시도 1 실패 사례로 기록하기 좋다.** 원인 분석: "수정하지 마"를 프롬프트에 쓰지 않았거나, 감도·FOV를 바꾸려면 기존 클래스에 훅이 필요했던 설계상 이유가 있었을 수 있다.

## 2장 — 적 AI와 웨이브 시스템

### 2-1. 체력/데미지 설계 논의
- **프롬프트 핵심**: "코드는 아직 쓰지 마" + "2~3가지 안을 장단점과 함께" + "결정은 내가 한다".
- **결정해야 할 4가지**: ① IDamageable 메서드 ② 사망 처리 주체 ③ UI 갱신 방식(CLAUDE.md에 따라 이벤트) ④ 무적 시간.
- **실제 선택(코드로 확인)**: `IDamageable` + `Health` 분리, 파괴는 Health 밖에서 처리 → `DestroyOnDeath.cs`.
- **직접 채울 것**: 고른 이유(AI가 제시한 이유가 아니라 **본인의 이유**).

### 2-2. 체력과 데미지 구현 — 커밋 `e9552d5`
- **결과**: `IDamageable.cs`, `Health.cs`, `WeaponSystem.cs`(+9) 외에 **`DestroyOnDeath.cs`가 추가로 생겼다.**
- **⚠ 확인할 것**: 프롬프트는 "파일 2개만"이었다. DestroyOnDeath를 본인이 요청했는지, AI가 알아서 만들었는지 `git diff`를 보고 기록한다. 요청하지 않았다면 이것이 "요청하지 않은 변경" 사례다.

### 2-3. 적 AI — 커밋 `4f79ade`
- **프롬프트 핵심**: enum + switch 상태(Idle/Chase/Attack/Dead), 추적 60m·공격 2m, Health 재사용, OnDisable 구독 해제, 플레이어를 넣어 주는 공개 메서드.
- **결과**: `EnemyAI.cs`(170줄), `Enemy.prefab`.
- **교훈**: 프리팹은 씬 오브젝트를 참조할 수 없다. Stopping Distance 1.8은 공격 거리 2m에서, 추적 거리 60m는 아레나 대각선 약 57m에서 나온 값이다(매직 넘버 금지 원칙).

### 2-4. 웨이브 시스템 — 커밋 `4a61045`
- **결과**: `WaveData.cs`, `WaveSpawner.cs`(138줄), `Wave_1~3.asset`.
- **교훈**: MCP는 씬 오브젝트 배열(`Transform[]`)을 채우지 못한다. 그래서 부모(SpawnPoints) 하나만 받아 자식을 모으는 구조로 바꿨다. **도구의 한계가 설계를 바꾼 사례**다.

### 2-5. 오브젝트 풀링 리팩터링 — 커밋 `d522383`
- **결과**: `EnemyPool.cs`(68줄) 신규, `Health.cs`(+3, 체력 초기화), `EnemyAI.cs`(+25, 상태 초기화), `WaveSpawner.cs`(±9).
- **판정 포인트**: "밖에서 보면 안 바뀌었는가" → 2웨이브 적이 체력 30으로 나오고, Dead 상태로 굳어 있지 않은지 확인한다. 공개 이벤트 시그니처가 유지됐는지도 diff로 확인한다.
- **직접 채울 것**: 본인의 판정(예/아니오 + 근거).

### 2-6. 과제 — 원거리 + 돌진 적(둘 다) · 커밋 `4aa8e63`
- **결과**: `EnemyBase.cs`, `RangedEnemyAI.cs`, `ChargerEnemyAI.cs`, `EnemyProjectile.cs`, `ShockwaveVisual.cs`, 프리팹 3개, `EnemyPool`/`WaveSpawner`/`WaveData` 수정. 스크립트 5개를 새로 만들고 3개를 수정했다.
- **⚠ 확인할 실패 후보**: 과제는 "둘 중 하나", 그리고 CLAUDE.md는 "한 번에 파일 1~2개, 5개 이상 생성 금지"다. 한 커밋에 새 스크립트 5개가 들어갔다. 또 `EnemyBase`를 도입하면서 기존 `EnemyAI` 구조가 결국 바뀌었다(3-4에서 `EnemyAI.cs` 삭제 → `MeleeEnemyAI.cs`).
  → "기존 EnemyAI를 수정하지 않는다" 조건과 충돌한다. 실패 사례로 분석하기 좋다.

## 3장 — 완성과 검증

### 3-1. 게임 상태 머신 — 커밋 `8676da2`
- **결과**: `GameManager.cs`(176줄). 플레이어 Health 500(적 데미지 10 × 50대), 웨이브 5개.
- **핵심 함정**: `timeScale = 0`이어도 Update와 입력은 멈추지 않는다 → 조작 컴포넌트를 꺼야 한다. 배열 대신 타입이 좁은 칸 두 개로 받는다.

### 3-2. HUD — 커밋 `4eac05f`
- **결과**: `HUDController.cs`(163줄), `EnemyHealthBar.cs`(요청 범위 밖 추가). `WeaponSystem`에는 탄약 이벤트, `WaveSpawner`에는 킬 이벤트를 넣었다.
- **함정 4개**: Canvas가 World Space로 기본 설정됨, `fillAmount`는 스프라이트가 없으면 동작하지 않음, 해상도 때문에 가장자리가 잘림, Play 중 수정이 거부됨. TMP를 쓰면 한글이 □로 나온다.
- **⚠ 확인할 것**: 이 커밋에서 `ChargerEnemy`/`RangedEnemy` 프리팹도 크게 바뀌었다(+229/+228). HUD 작업과 무관한 변경이 섞였는지 확인한다.

### 3-3. 게임필 — 커밋 `b162244`
- **관찰 질문**: AI가 1번(플래시)만 만들었나, 3개를 다 만들었나?
- **git 근거**: 한 커밋에 `HitFlash`(1번), `CameraShake`(2번), `HitParticles`(3번)에 더해 요청 목록에 없던 `WeaponKick`, `PlayerRecoil`까지 들어갔다.
  → **3개 + α가 한꺼번에 커밋됐다.** 단계마다 테스트하고 커밋하라는 절차를 지키지 않은 것인지, AI가 범위를 넘은 것인지 기록해야 한다.

### 3-4. AI 코드 리뷰 — 커밋 `f34a996`
- **3개만 고친 결과**: 새 파일 `KillCounter`(킬 집계 분리, 이벤트 시그니처 유지), `RequiredReference`(Awake에서 null 참조를 검사하고 비활성화), `EnemyAI` → `MeleeEnemyAI` 교체, `GameManager`가 `StartWaves()`를 호출하도록 변경 등.
- **⚠ 확인할 것**: "3건 반영"인데 **20개 파일**이 바뀌었다. "리뷰 수정이 멀쩡한 코드를 망가뜨린다"는 경고에 해당하는지 4단계 플레이 테스트 결과로 판정한다.

| # | AI의 지적 | 내 판정 | 근거 |
| - | --------- | ------- | ---- |
| 1 | (WaveSpawner가 킬 집계까지 맡아 책임이 섞였다) | 맞다? | `WaveSpawner.cs` → `KillCounter` 분리 |
| 2 | (인스펙터 참조 누락 시 NRE 위험) | 맞다? / 애매하다? | `RequiredReference.Check` 도입 |
| 3 | (**틀린 지적을 직접 찾아 채울 것**) | 틀렸다 | 예: 이미 OnDisable에서 해제하는데 "해제 누락", RequireComponent로 보장되는데 "null 체크 필요" |

> 위 1·2행은 커밋에서 역추적한 **추정**이다. 실제 리뷰 출력과 맞춰 고쳐야 한다.

### 3-5. 빌드
- `Builds/` 폴더가 프로젝트 **안에** 있다. 문서는 프로젝트 **밖**에 출력하라고 한다(.gitignore에 걸리지 않으면 리포에 들어가기 때문). `git status`로 Builds가 추적되지 않는지 확인한다.
- `Application.Quit()`(Esc 종료)은 exe에서만 검증할 수 있다.
